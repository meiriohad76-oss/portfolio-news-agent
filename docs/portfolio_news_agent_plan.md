# Portfolio News Agent - Product Design and Implementation Plan

## 1. Product Design Document

### 1.1 Purpose

The Portfolio News Agent monitors unread Seeking Alpha emails, opens linked articles using the user's paid Seeking Alpha session, determines whether each article is relevant to stocks or commodity exposures in the user's uploaded portfolio file, stores structured summaries in a local database, sends concise Telegram alerts, and marks successfully processed relevant emails as read.

The first testing version is a manual one-shot command. Scheduling, local LLM fallback, and cloud integration are intentionally out of scope for v1.

### 1.2 Goals

- Import the user's portfolio from an uploaded Excel or CSV file.
- Scan Gmail for unread emails from `account@seekingalpha.com`.
- Extract Seeking Alpha article links from those emails.
- Open article links in a persistent browser profile.
- Reuse Seeking Alpha login cookies when possible.
- Pause for manual login or manual challenge completion when needed.
- Analyze articles with OpenAI only.
- Identify whether the article is relevant to one or more portfolio assets.
- Map commodity themes to affected portfolio holdings when appropriate.
- Store metadata and structured summary fields in SQLite.
- Send one Telegram private-chat message per relevant portfolio asset per article.
- Mark emails as read only after successful relevant processing.
- Leave irrelevant or failed emails unread.

### 1.3 Non-Goals

- No cloud database or cloud execution in v1.
- No watchlist support in v1.
- No local LLM fallback in v1.
- No bypassing bot detection, CAPTCHA, anti-automation protections, paywalls, or access controls.
- No storage of full article text unless explicitly added later.
- No trading decisions or recommendations generated by the agent.
- No Hebrew summary support in v1.
- No fully automatic first-time Seeking Alpha login.

### 1.4 Compliance and Access Boundary

The agent may:

- Use a normal browser session.
- Persist browser cookies/session state.
- Ask the user to log in manually.
- Ask the user to complete any access challenge manually.
- Continue article extraction after the user confirms access is ready.

The agent must not:

- Attempt to defeat bot detection.
- Circumvent CAPTCHA or challenge systems.
- Spoof identity or traffic in a way intended to evade protections.
- Extract content the user cannot access through their normal paid session.

If access fails, the agent records the failure locally and leaves the Gmail email unread.

### 1.5 User Workflow

1. User places the latest portfolio workbook in a configured local path.
2. User runs:

   ```bash
   python run_agent.py --once
   ```

3. Agent loads config and validates required credentials.
4. Agent imports portfolio symbols from the workbook.
5. Agent queries Gmail for unread emails from `account@seekingalpha.com`.
6. For each unread email:
   - Extract article URL(s).
   - Skip URLs already processed successfully.
   - Open the article in a persistent browser profile.
   - If Seeking Alpha login/challenge is required, pause and prompt the user to complete it.
   - Extract headline, date, author, and article body text where available.
   - Ask OpenAI to classify relevance to portfolio assets and commodity exposures.
   - For each relevant asset, ask OpenAI to produce structured fields.
   - Save article and per-asset summaries to SQLite.
   - Send one Telegram message per relevant asset.
   - Mark the Gmail message as read only if at least one relevant summary was successfully saved and sent.
7. Irrelevant emails remain unread, but are recorded locally as seen/irrelevant to avoid repeated work in the same version.
8. Failed emails remain unread and are retried on the next run.

### 1.6 Portfolio Import Design

The sample workbook includes a clean tab named `Excel view including prices`, which should be the preferred source when present.

Preferred columns:

- `Symbol`
- `Name`
- `Price`
- `Quant Rating`
- `SA Analyst Ratings`
- `Wall Street Ratings`

Import rules:

- Treat all clean rows in the configured portfolio file as current portfolio holdings.
- A valid symbol is a short uppercase ticker-like value, for example `AEM`, `ASML`, `QQQ`, `SILJ`, `BRK.B`.
- Ignore rows where `Symbol` is numeric, blank, a date, or otherwise not ticker-like.
- If `Excel view including prices` is missing, fall back to the first sheet with a `Symbol` column.
- Preserve existing ratings from the portfolio file for context.
- Store a file hash and import timestamp so future runs can tell whether the portfolio changed.

### 1.7 Commodity Mapping Design

Commodity articles should be mapped to relevant portfolio holdings from the current file.

Initial commodity theme mapping:

- Gold / precious metals:
  - companies or ETFs whose name, sector, or industry indicates gold, mining, precious metals, or royalty/streaming exposure.
  - examples from the sample file: `AEM`, `NEM`, `WPM`, `B`, `SILJ`.
- Silver:
  - companies or ETFs whose name indicates silver exposure.
  - examples from the sample file: `PAAS`, `SILJ`, `WPM`.
- Oil / crude / energy:
  - companies or ETFs whose name, sector, or industry indicates oil, gas, energy, E&P, or energy sector exposure.
  - examples from the sample file: `CVX`, `PR`, `XLE`.
- Copper:
  - companies or ETFs whose name indicates copper exposure.
  - example from the sample file: `ERO`.

Important rule:

Commodity detection is not enough by itself. The LLM must decide whether the article materially affects each mapped portfolio asset. The agent should avoid sending alerts for every commodity-related holding unless the article's theme broadly applies.

### 1.8 Gmail Design

Search query:

```text
from:account@seekingalpha.com is:unread
```

Behavior:

- Process unread messages only.
- Extract Seeking Alpha article URLs from the email HTML/text body.
- Store Gmail message ID, thread ID, sender, subject, received timestamp, and processing status.
- Mark as read only after successful relevant processing.
- Leave irrelevant emails unread.
- Leave failed emails unread.

Status model:

- `new`
- `irrelevant_seen`
- `processed_relevant`
- `failed_access`
- `failed_extract`
- `failed_llm`
- `failed_telegram`

### 1.9 Article Access Design

Use Playwright with a persistent browser profile directory, for example:

```text
data/browser-profile/
```

Behavior:

- Launch visible browser by default for testing.
- Reuse cookies and login state between runs.
- If the article page indicates login is required, pause and show the user a terminal prompt:

  ```text
  Please log in to Seeking Alpha in the opened browser, then press Enter here to continue.
  ```

- If the page presents a challenge or access check, pause and ask the user to complete it manually.
- After confirmation, continue extracting article metadata and text.
- If article access still fails, record failure and leave the Gmail email unread.

### 1.10 OpenAI Analysis Design

Use OpenAI only in v1.

Recommended model flow:

- `gpt-5-nano` for initial relevance classification.
- `gpt-5-mini` for final structured summaries if the article is long, multi-stock, ambiguous, or high priority.
- In early testing, use one configurable model to simplify debugging.

The LLM must return strict JSON. The application validates JSON with a schema before saving or sending.

The LLM must distinguish:

- Author's rating.
- Seeking Alpha Quant rating from the portfolio file or article if explicitly present.
- Wall Street rating from the portfolio file or article if explicitly present.
- Agent inferred sentiment based on the article content.

The agent inferred sentiment should be one of:

- `bullish`
- `somewhat_bullish`
- `neutral`
- `mixed`
- `somewhat_bearish`
- `bearish`
- `unclear`

Action relevance should be one of:

- `ignore`
- `monitor`
- `earnings`
- `valuation`
- `price_target`
- `thesis_change`
- `risk_warning`
- `material_news`
- `possible_action`

### 1.11 Summary Format

One summary row and one Telegram message per stock per article.

Required fields:

- Article date.
- Headline.
- Source URL.
- Portfolio symbol.
- Company or ETF name.
- Theme for the stock: bullish, bearish, mixed, neutral, or unclear.
- Author rating, if present.
- Seeking Alpha Quant rating.
- Wall Street rating.
- Agent inferred sentiment.
- Price targets, if present.
- Other concrete forward-looking data, if present.
- Action relevance.
- Short summary of approximately three concise lines.
- Confidence score.

Telegram message format:

```text
{SYMBOL} - {inferred_sentiment} - {action_relevance}
{headline}

Author rating: {author_rating}
Quant: {quant_rating} | Wall St: {wall_street_rating}
Forward data: {price_targets_or_forward_data}

{short_summary}

{source_url}
```

### 1.12 Storage Design

Use SQLite at:

```text
data/portfolio_news.db
```

Suggested schema:

```sql
CREATE TABLE portfolio_imports (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_path TEXT NOT NULL,
  source_hash TEXT NOT NULL,
  imported_at TEXT NOT NULL
);

CREATE TABLE assets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  import_id INTEGER NOT NULL,
  symbol TEXT NOT NULL,
  name TEXT,
  asset_type TEXT,
  priority INTEGER NOT NULL DEFAULT 1,
  price REAL,
  quant_rating TEXT,
  sa_analyst_rating TEXT,
  wall_street_rating TEXT,
  metadata_json TEXT,
  UNIQUE(import_id, symbol),
  FOREIGN KEY(import_id) REFERENCES portfolio_imports(id)
);

CREATE TABLE gmail_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  gmail_message_id TEXT NOT NULL UNIQUE,
  gmail_thread_id TEXT,
  sender TEXT,
  subject TEXT,
  received_at TEXT,
  status TEXT NOT NULL,
  status_detail TEXT,
  first_seen_at TEXT NOT NULL,
  last_attempt_at TEXT
);

CREATE TABLE articles (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  canonical_url TEXT NOT NULL UNIQUE,
  source_url TEXT NOT NULL,
  headline TEXT,
  author TEXT,
  article_date TEXT,
  source TEXT NOT NULL DEFAULT 'Seeking Alpha',
  content_hash TEXT,
  first_seen_at TEXT NOT NULL
);

CREATE TABLE article_asset_summaries (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  article_id INTEGER NOT NULL,
  gmail_message_id INTEGER NOT NULL,
  symbol TEXT NOT NULL,
  company_name TEXT,
  author_rating TEXT,
  quant_rating TEXT,
  wall_street_rating TEXT,
  inferred_sentiment TEXT NOT NULL,
  theme TEXT,
  price_targets_json TEXT,
  forward_data_json TEXT,
  action_relevance TEXT NOT NULL,
  short_summary TEXT NOT NULL,
  confidence REAL,
  llm_model TEXT,
  prompt_version TEXT,
  created_at TEXT NOT NULL,
  UNIQUE(article_id, symbol),
  FOREIGN KEY(article_id) REFERENCES articles(id),
  FOREIGN KEY(gmail_message_id) REFERENCES gmail_messages(id)
);

CREATE TABLE runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  started_at TEXT NOT NULL,
  finished_at TEXT,
  mode TEXT NOT NULL,
  emails_found INTEGER DEFAULT 0,
  articles_processed INTEGER DEFAULT 0,
  summaries_created INTEGER DEFAULT 0,
  status TEXT NOT NULL,
  error TEXT
);
```

### 1.13 Configuration Design

Use `.env` for secrets:

```text
OPENAI_API_KEY=
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Use `config.yaml` for non-secret settings:

```yaml
portfolio_file: "C:/Users/meiri/Downloads/Portfolio 2026-05-23.xlsx"
gmail_sender: "account@seekingalpha.com"
database_path: "data/portfolio_news.db"
browser_profile_dir: "data/browser-profile"
openai_model: "gpt-5-nano"
telegram_enabled: true
mark_relevant_as_read: true
leave_irrelevant_unread: true
```

### 1.14 Error Handling

- Portfolio import failure:
  - Stop run.
  - Do not touch Gmail.
- Gmail API failure:
  - Stop run.
  - Record run failure.
- Article access failure:
  - Record failure.
  - Leave email unread.
- Article extraction failure:
  - Record failure.
  - Leave email unread.
- LLM validation failure:
  - Retry once with stricter repair prompt.
  - If still failing, record failure and leave email unread.
- Telegram failure:
  - Record failure and leave email unread so the alert can be retried.
- Successful irrelevant result:
  - Record `irrelevant_seen`.
  - Leave email unread.

### 1.15 Security and Privacy

- Store secrets only in `.env`, not in git.
- Store Gmail OAuth tokens locally under `data/secrets/`.
- Restrict local file permissions where possible.
- Do not log article text, OpenAI API keys, Telegram tokens, or Gmail tokens.
- Store only article metadata and summaries, not full article body text.
- Redact secrets in error output.

### 1.16 Future Versions

V2 candidates:

- Twice-daily scheduler.
- NYSE holiday/weekend handling.
- Local LLM fallback.
- More advanced dashboard.
- Watchlist support.
- Better commodity exposure configuration.
- Telegram digest mode.
- Backtesting exports.
- Article relevance feedback loop.

## 2. Implementation Plan

Create the Python project structure, dependency file, base CLI, config loading, logging, and data directories.

Proposed files:

- `run_agent.py`
- `portfolio_news_agent/config.py`
- `portfolio_news_agent/logging_setup.py`

### Ticket 2 - SQLite Schema and Repository Layer

Definition of Done:

Testing:

Testing:

### Ticket 4 - Commodity Exposure Mapper

## 4. V1 Acceptance Criteria

V1 is complete when:

- The agent runs via `python run_agent.py --once`.
- The sample portfolio workbook imports correctly.
- Only unread Gmail messages from `account@seekingalpha.com` are scanned.
- The agent can open a Seeking Alpha article in a persistent browser session.
- Manual login/challenge completion is supported.
- Relevant article-stock summaries are stored in SQLite.
- One Telegram private-chat message is sent per relevant stock.
- Relevant successfully processed email is marked read.
- Irrelevant emails remain unread.
- Failed emails remain unread.
- Duplicate successfully processed article URLs are not processed again.
- No full article text is stored in the database.
- OpenAI is the only LLM provider used.
